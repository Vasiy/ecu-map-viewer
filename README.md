# ECU map viewer

Просмотрщик калибровочных карт ЭБУ Magneti Marelli **IAW 5AM** (Ducati / Moto Morini).
Читает дамп прошивки `.bin` вместе с его описанием `.xdf` (TunerPro) и строит
трёхмерные поверхности — карты зажигания, топлива и любые другие таблицы из XDF.
Несколько прошивок показываются в одной сцене внахлёст, чтобы видеть расхождения
калибровок: резкие перепады, несглаженные швы, разную форму карты между платформами.

Приложение — статическая страница без сборки и без сети: открывается локально,
так же кладётся на плату (см. «Интеграция в onboard-logger»).

## Запуск

```bash
python3 -m http.server 8123      # из корня репозитория
open http://127.0.0.1:8123/
```

`file://` тоже работает, но локальный сервер надёжнее (некоторые браузеры режут
чтение файлов со страницы, открытой с диска).

## Как пользоваться

1. Перетащите в левую панель `.bin` и `.xdf` — **имена файлов должны совпадать**
   (`granpasso.bin` + `granpasso.xdf`). Можно бросить сразу несколько пар.
2. В поле **Карта** выберите таблицу — в XDF их десятки (у granpasso.xdf это 28
   поверхностей и 52 кривые). Верхняя группа — роли: одна и та же карта
   называется по-разному в разных описаниях (`Ignition Main advance`,
   `Ignition - Main`, `Ignition map`), роль сводит их вместе, и все прошивки
   рисуются одним выбором. Ниже — точные названия таблиц из XDF.
3. Чекбокс в карточке включает и выключает поверхность. Ось Z и цветовые шкалы
   пересчитываются **только по видимым** датасетам.
4. Одномерная таблица (группа **Кривые**) рисуется обычным двумерным графиком —
   по одной линии на видимую прошивку; в карточке вместо термокарты появляется
   спарклайн, а органы управления сценой прячутся, им нечем управлять.
5. Имя в карточке правится прямо на месте — оно и попадает в подсказку под курсором
   и в подпись кривой на сечении.

Управление сценой: вращение — перетаскивание мышью или свайп; масштаб — колесо или
щипок; наведение показывает обороты, ДПДЗ и значение ячейки.

**Разница** — вычитание: выбранная база остаётся эталоном, остальные поверхности
показывают дельту к ней. Оси у платформ отличаются (2.4° против 2.2° в первой точке
ДПДЗ), поэтому карта пересчитывается билинейно на сетку базы, а не по номерам ячеек.

**Сечение** — срез при фиксированных оборотах или фиксированном ДПДЗ. Он рисуется
сразу в двух местах: линией прямо на поверхностях (у каждой прошивки — своя, в её
цвете) и двумерным графиком под сценой. Ползунок двигает обе картинки одновременно.
Точки осей у платформ разные, поэтому линия прижимается к собственной оси своей
прошивки — иначе она висела бы в воздухе рядом с краем поверхности.

**PNG** сохраняет текущий вид сцены.

### Прошивка без XDF

Если для `.bin` нет одноимённого `.xdf`, в карточке появляется выбор пресета —
встроенный адрес таблицы Ignition Main и оси этого семейства ЭБУ:

| Платформа | Адрес |
|---|---|
| Moto Morini Granpasso (23EC) | `0x4856E` |
| Ducati Multistrada 1100 DP | `0x484DE` |
| Ducati 1198 Stock | `0x48634` |
| Ducati Hypermotard 1100 | `0x4856E` |

Пресет — это запасной вариант: свой XDF всегда точнее, потому что несёт настоящие
оси, формулы и все остальные таблицы.

## Что читается из XDF

- `<XDFTABLE>` → название, категории, три оси;
- `EMBEDDEDDATA`: адрес, размер ячейки, шаги строк и столбцов, флаги типа
  (`0x01` знаковое, `0x02` little-endian, `0x04` плавающая точка), в отсутствие
  флагов — `<DEFAULTS>` из заголовка;
- `<MATH equation="X/10">` — формула вычисляется собственным парсером
  (сортировочная станция), а не `eval`: чужой XDF не должен исполнять код на странице;
- значения осей берутся, в порядке приоритета, из связанной таблицы-легенды
  (`<embedinfo linkobjid=...>`, так хранятся точки RPM и ДПДЗ в 5AM), из
  собственного адреса оси, из статических `<LABEL>`, иначе — номер ячейки.

Карта Ignition Main в этом семействе — 32 точки RPM × 20 точек ДПДЗ, `uint16 LE`,
угол = `raw / 10`.

## Тесты

```bash
node tests/run.js        # офлайн-набор: XML, формулы, чтение бинаря, XDF, сетка
```

Браузерная проверка (нужны playwright и chromium, тестовые прошивки в `testdata/`):

```bash
python3 -m http.server 8123 &
npm i playwright && npx playwright install chromium
node tests/browser.mjs   # печатает отчёт: контуры, диапазоны осей, срез, разница, PNG
```

`testdata/` не коммитится — прошивки кладутся туда локально.

## Интеграция в onboard-logger

Зависимостей и сборки нет, Plotly лежит рядом в `vendor/`, поэтому страница
работает на плате без интернета (в режиме точки доступа его и нет). Порядок:

1. скопировать `js/`, `css/`, `vendor/`, `index.html` в `app/static/maps/`;
2. отдать каталог статикой (`main.py` уже раздаёт `/static/*` с `Cache-Control: no-cache`);
3. строки уже вынесены в `js/i18n.js` по тем же правилам (`t(key)`, `data-i18n`) —
   при переносе ключи переезжают в общий `app/static/i18n.js` со всеми 8 локалями.

## Структура

| Файл | Назначение |
|---|---|
| `js/xml.js` | минимальный разбор XML (один и тот же код в браузере и в node) |
| `js/expr.js` | вычисление формул `MATH` без `eval` |
| `js/binio.js` | чтение ячеек из образа по геометрии `EMBEDDEDDATA` |
| `js/xdf.js` | модель XDF: таблицы, оси, чтение таблицы из прошивки |
| `js/presets.js` | встроенные описания для `.bin` без XDF |
| `js/grid.js` | диапазоны, билинейная выборка, разница, сечения |
| `js/viewer.js` | слой Plotly: поверхности, контуры, диапазоны осей |
| `js/app.js` | загрузка файлов, датасеты, режимы |
| `js/i18n.js` | строки интерфейса (ru/en) |
