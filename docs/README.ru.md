# Просмотрщик карт ЭБУ

Читает дампы прошивок Magneti Marelli **IAW 5AM** (Ducati / Moto Morini) через их описания
`.xdf` из TunerPro и рисует калибровочные таблицы — зажигание, топливо и любые другие
таблицы из описания — трёхмерными поверхностями. Несколько прошивок ложатся в одну сцену,
и сразу видно, где калибровки расходятся: ступенька там, где должно быть гладко,
несглаженный шов между точками сетки, другая форма карты на другой платформе.

Это статическая страница: без сборки, без зависимостей, без сети. Работает из папки, из
контейнера или с платы, которая раздаёт собственную точку доступа.

## Запуск

### В Docker

```bash
docker build -t ecu-map-viewer .
docker run --rm -p 8123:8123 ecu-map-viewer
```

Или через Compose:

```bash
docker compose up --build
```

Дальше откройте <http://127.0.0.1:8123/>. Контейнер отдаёт те же файлы и тем же самым
`serve.py`, что и локальный запуск; в интернет программа не ходит ни на одном шаге. Другой
порт задаётся пробросом: `docker run --rm -p 9000:8123 ecu-map-viewer`.

### Без Docker

Нужен только Python 3 — он есть в macOS и в любом дистрибутиве Linux:

```bash
python3 serve.py          # http://127.0.0.1:8123/
python3 serve.py 9000     # другой порт
```

Можно открыть `index.html` прямо с диска, но с локальным сервером надёжнее: некоторые
браузеры ограничивают то, что странице позволено читать по `file://`.

`serve.py` отдаёт файлы с `Cache-Control: no-store`. Это важно после обновления: `python3
-m http.server` заголовков кэширования не шлёт вовсе, и браузер может оставить у себя
старый `index.html` рядом со свежим `js/app.js`.

## Загрузка прошивки

Перетащите `.bin` и его `.xdf` в левую панель или нажмите **Выбрать файлы**. **Совпадающие
имена связываются сами** — `firmware.bin` + `firmware.xdf`. Пар можно бросить сколько
угодно: каждая станет карточкой в списке со своим цветом.

Имя в карточке правится прямо на месте. Что впишете, то и попадёт в подсказку под
курсором, в легенду и в подпись кривой сечения.

### Одно описание на несколько прошивок

Совпадение имён — удобство, а не правило. На каждой карточке есть **выбор описания**: в
списке все `.xdf`, загруженные за сеанс, и встроенные пресеты, и сколько угодно карточек
могут указывать на одно и то же описание.

Так быстрее всего сравнивать версии одной калибровки: бросьте образы вместе с одним `.xdf`,
имя которого не совпадает ни с одним из них, — он достанется сразу всем. Больше не нужно
копировать описание под каждый образ и переименовывать копии. Если бросить два описания и
больше, ничего не предполагается — выберите их по карточкам.

Выбор запоминается по имени файла, поэтому в следующий раз прошивка снова найдёт своё
описание.

### Файлы, лежащие на устройстве

Если указать каталог данных — `python3 serve.py --data ~/firmware` — viewer покажет и то,
что в нём уже лежит, и загрузит файл одним щелчком: перетаскивать одно и то же каждый раз
больше не нужно. Брошенный руками `.xdf` туда сохраняется, образы прошивок — нет:
перетащить прошивку обычно значит посмотреть, а не положить.

Контейнер монтирует для этого `./data`. Он слушает все интерфейсы, поэтому запись там
отклоняется, пока не выставлен `ALLOW_REMOTE_WRITES=1` — что `docker-compose.yml` и делает,
открытым текстом. Без каталога данных никакой библиотеки нет вовсе, и страница ведёт себя
ровно как раньше.

### .bin без .xdf

В карточке появится выбор пресета: встроенный адрес таблицы Ignition Main и оси, общие для
этого семейства ЭБУ.

| Платформа | Адрес |
|---|---|
| Moto Morini Granpasso (23EC) | `0x4856E` |
| Ducati Multistrada 1100 DP | `0x484DE` |
| Ducati 1198 Stock | `0x48634` |
| Ducati Hypermotard 1100 | `0x4856E` |

Пресет — запасной вариант. Свой XDF всегда точнее: в нём настоящие оси, настоящие формулы
пересчёта и все остальные таблицы.

## Выбор карты

В XDF десятки таблиц, поэтому селектор **Карта** разбит на группы:

- **Одна карта на разных платформах** — роли. Одна и та же таблица в каждом описании
  зовётся по-своему (`Ignition Main advance`, `Ignition - Main`, `Ignition map`), роль
  сводит их вместе, и один выбор рисует все прошивки.
- **Поверхности (3D)** — точные названия из описания.
- **Кривые (1D)** — одномерные таблицы, рисуются обычным двумерным графиком.

Роли покрывают основные карты и обычные коррекции — дельту, температуру воздуха и двигателя, прогрев, фазу, максимальный момент. Точные названия сопоставляются без учёта пунктуации и меток вроде `[corsaro]`, поэтому `Fuel - Main` и `Fuel Main` попадают в одну строку.

Счётчик рядом (`2/3`) говорит, в скольких загруженных прошивках эта таблица есть. Та, где
её нет, помечается красным в своей карточке.

## Сравнение

- Вращение — перетаскиванием, масштаб — колесом, наведение показывает обороты, дроссель и
  значение ячейки.
- Чекбокс в карточке включает и выключает поверхность. **Ось Z и цветовые шкалы считаются
  только по видимым прошивкам** — стоит снять галочку, и сцена растягивается по тому, что
  осталось. Горб на одной карте не может «исчезнуть» из-за карты, на которую вы сейчас не
  смотрите.
- У каждой поверхности своя цветовая шкала, поэтому включение одной не перекрашивает
  остальные.
- Контуры рисуются на самой поверхности и проецируются на все три плоскости: пол
  (обороты × дроссель), заднюю стенку (дроссель × значение) и боковую (обороты × значение).

**Разница** делает выбранную базу эталоном, а остальные показывает дельтой к ней. Точки
осей у платформ отличаются (2.4° против 2.2° в первой точке дросселя), поэтому карта
пересчитывается на оси базы билинейно, а не сопоставляется по номерам ячеек.

**Сечение** режет карту при фиксированных оборотах или фиксированном угле дросселя. Срез
показывается сразу дважды: линией прямо на поверхностях, у каждой прошивки в её цвете, и
двумерным графиком под сценой. Ползунок двигает обе картинки.

**PNG** сохраняет текущий вид. Кнопка **i** справа вверху — короткое описание и ссылка на
репозиторий.

## Воспроизведение лога поездки

Бросьте декодированный лог из **onboard-logger** (`.csv`: `time` и каналы, которые эта
поездка записала) рядом с загруженной прошивкой, либо, работая как дополнение, выберите его
из **Записанные поездки** в боковой панели. Сопоставьте два его канала с осями текущей
карты — обороты и дроссель угадываются для основных карт зажигания и топлива, если лог несёт
оба; любая другая таблица требует выбора вручную, поскольку ничто в XDF не говорит, что
значит каждая ось, — и лог проигрывается через собственный поиск по таблице, ячейка за
ячейкой.

Три вида под сценой:

- **Воспроизведение** — предсказанное таблицей значение во времени рядом с тем, что лог
  реально измерил для неё (УОЗ, время впрыска…). Разница между ними — это все коррекции,
  которых не видно в базовой карте; близкое совпадение на ровном крейсерском ходу
  подтверждает, что сопоставление и единицы измерения верны.
- **Время в ячейке** — тепловая карта в форме таблицы, окрашенная по тому, сколько времени
  поездка провела в каждой ячейке.
- **Путь** из точек прямо на поверхности, по одной на каждый замер, включаемый галочкой.

Это честно про карты на установившемся режиме и их обычные коррекции. Он не показывает
переходное обогащение при резком открытии дросселя — эта коррекция в реальной прошивке
считается по скорости изменения и состоянию плёнки топлива на стенках, а не по таблице, а лог
с частотой раз в секунду всё равно не различит несколько сотен миллисекунд.

Воспроизведение идёт сразу по всем видимым прошивкам, так что одна поездка может показать,
как на неё ответила бы каждая из калибровок.

## Язык и оформление

Тринадцать языков, переключаются в шапке: English, Čeština, Deutsch, Español, Français,
Italiano, Nederlands, Polski, Suomi, Svenska, Ελληνικά, Български, Русский. Пока выбора не
было, берётся язык браузера, а если он не переведён — английский. Есть светлая и тёмная
темы; оба выбора запоминаются в браузере.

## Что читается из XDF

- `<XDFTABLE>` → название, категории, три оси;
- `EMBEDDEDDATA`: адрес, размер ячейки, шаги строк и столбцов, флаги типа (`0x01` знаковое,
  `0x02` little-endian, `0x04` плавающая точка), а при отсутствии флагов — `<DEFAULTS>` из
  заголовка;
- `<MATH equation="X/10">` вычисляется собственным парсером (сортировочная станция), а не
  `eval`: чужой XDF не должен исполнять код на странице;
- значения осей берутся из связанной таблицы-легенды (`<embedinfo linkobjid=...>` — именно
  так файлы 5AM хранят точки оборотов и дросселя), из собственного адреса оси, из
  статических `<LABEL>`, а если ничего этого нет — из номера ячейки.

Карта Ignition Main в этом семействе — 32 точки оборотов × 20 точек дросселя, `uint16 LE`,
угол = `raw / 10`.

```bash
python3 serve.py &
npm i playwright && npx playwright install chromium
node tests/browser.mjs   # контуры, диапазоны осей, сечение, разница, PNG
```

## Как дополнение к onboard-logger

Ни зависимостей, ни сборки, а Plotly лежит в `vendor/`, поэтому страница работает на плате без
выхода в интернет. Упаковать её дополнением умеет `./release-addon.sh`:

```bash
./release-addon.sh    # dist/ecu-map-viewer-addon-<версия>-<sha>.tar.gz
```

Этот архив ставится в onboard-logger через **Config → System → Дополнения**. Плата раздаёт
страницу и держит рядом хранилище для описаний — ни строчки этого кода она не выполняет, а при
удалении дополнения уходят и его файлы.

На вкладке Firmware появляется **Показать карту** рядом с *Diff 2 .bin*: отметьте один или
несколько образов, и они откроются здесь, во вкладке, которая переиспользуется, а не плодится.
Бросьте `.xdf` один раз — он останется на плате, и следующее нажатие сразу нарисует карты.
